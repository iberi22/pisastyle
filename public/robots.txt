# robots.txt — PISAStyle
#
# This site wants to be READ by answer engines and does not want to be CONSUMED
# into training sets. Those two pull in opposite directions, so `Allow: /` alone
# cannot express both: the same vendors that run the retrieval crawlers run the
# training crawlers, under DIFFERENT user-agent tokens. Every token below is
# named explicitly because the whole point of this file is the distinction.
#
# ── HOW THE VENDORS ACTUALLY SPLIT THEM (verified, not assumed) ─────────────
# OpenAI publishes three independent agents, and states the settings are
# independent of one another:
#   OAI-SearchBot — builds the ChatGPT search index. THIS is the token that
#                   decides whether the pages appear in cited answers.
#   GPTBot        — bulk crawl for training foundation models. Blocking it has
#                   NO effect on ChatGPT search.
#   ChatGPT-User  — a live user asked Claude/ChatGPT to open this URL.
# Anthropic publishes the same three-way split:
#   Claude-SearchBot — search indexing and citation.
#   ClaudeBot        — training data collection.
#   Claude-User      — user-initiated fetch.
#
# The common and expensive mistake is a copy-pasted "block all AI crawlers"
# list: it takes out the retrieval bots too, and the site vanishes from answers
# while the training opt-out looks like it worked. That is why the retrieval
# tokens are listed with an explicit `Allow` rather than left to the catch-all —
# some parsers apply the most specific matching block and inherit the strictest
# rule rather than treating a missing rule as "allowed".
#
# ── WHAT IS DELIBERATELY ABSENT, AND WHY ─────────────────────────────────────
# * No `llms.txt`. Measured with no effect across 300,000 domains, and John
#   Mueller (Google, June 2025) stated that no AI system currently uses it. It is
#   prospective infrastructure, not a ranking or citation signal. The map below
#   plus the JSON-LD in every page is the machine-readable surface that does
#   work.
# * No `FAQPage` JSON-LD. Google retired FAQ rich results on 7 May 2026 (a
#   three-phase deprecation). The schema remains valid as semantics but no longer
#   yields an enriched result, so it is not the primary mechanism anywhere here.
#   The FAQ on /explorar stays ordinary visible prose, which an answer engine can
#   quote whether or not rich results exist.
#
# The GEO study (Aggarwal et al., Princeton + IIT Delhi, arxiv 2311.09735)
# measured that citing credible sources raises share of voice in answer engines
# by 41%, statistics by 31% and verbatim quotes by 28%. That is a CONTENT
# result. What this file owes is narrower and concrete: make sure the crawlers
# that build citations can reach the pages carrying those citations, and shut
# the ones that only consume. Note also that 92.36% of AI Overviews cite a domain
# already in the organic top 10 — so hreflang, unique titles, canonical and the
# sitemap are the load-bearing work, and this file is the last mile.
